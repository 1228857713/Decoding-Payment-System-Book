# 单一书稿与推送发布设计

用户已确认：只维护一份章节文档，原始 PDF 不再参与后续维护，当前目录直接作为网站项目，推送后自动构建更新。

## 内容与目录

- 将现有公开网站工作树提升为根目录，保持现有公开仓库历史、站点地址和章节 URL。
- `docs/book/*.md` 是唯一章节内容源，原图保留在 `docs/book/assets/`。
- 网站侧栏和全书目录从章节标题、顺序动态生成，不维护重复目录清单。
- 删除重复导入流程和正文不可变哈希限制。校验改为文档结构、章节元数据、图片和站内链接检查。
- 原始 PDF、转换结果和校对档案已在私有备份仓库核验保存；从日常工作区清理，不合并私有 Git 历史。
- 旧私有 Git 元数据保存到工作区外的本机恢复目录，保留离线恢复能力。

## 构建与发布

- 保持 VitePress 1.6.4 和现有阅读功能，不新增后端、数据库或跨仓库凭据。
- 本地支持启动、检查、测试、构建、预览和清理可再生构建产物。
- PR 只执行检查、测试与构建；向 main 推送或手动触发时，成功构建后才部署 GitHub Pages。
- GitHub Pages 使用现有仓库子路径；Cloudflare 构建保留根路径支持，账号登录另行处理。
- 构建结果与依赖不提交 Git；失败的检查阻止新版本发布。

## 验收

- 迁移前后 22 个章节 Markdown 和 249 个图片文件的字节保持一致。
- 修改正文后检查成功；缺图、坏链接、冲突章节顺序会失败；新增章节可以进入自动目录。
- 本地与全新源码克隆都能检查、测试并构建。
- 两种 base 构建正确，原第五章、搜索、图片放大和手机阅读保持可用。
- 完成一次真实 main 推送，确认 Actions 成功并核对线上页面。
